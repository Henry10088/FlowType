## 1. 产品定义

说写把 Android 手机上的输入内容通过局域网实时同步到 Windows 当前光标位置。产品的核心场景是在手机上使用用户当前选择的系统输入法进行语音输入，让文字直接出现在电脑应用中。

产品定位语：

> 手机上说，电脑上写。

说写本身不提供语音识别引擎，不指定或切换输入法。V1 使用 Android 当前系统输入法提供的普通文本输入能力。

## 2. V1 目标

V1 建立以下完整闭环：

1. Android 使用普通原生多行文本输入框并唤起当前系统输入法。
2. 文本每次新增、删除或替换时，Android 发送带序号的完整文本状态。
3. Windows 根据上一次已应用状态计算差异，并注入当前目标窗口。
4. 语音识别对已有内容的修正、删除和替换能够继续同步。
5. 用户点击“新会话”结束当前输入会话；本段非空内容进入历史，后续不再修改该段内容。
6. 支持自动重连、明确状态、永久绑定和多电脑切换。
7. 局域网中的正文和认证信息全程加密传输。
8. 支持普通权限和管理员权限的 Windows 目标应用。
9. Android 和 Windows 发布包应尽可能小。
10. Android 提供可选悬浮输入模式，用户在其他应用上方也能快速开始同一套输入流程。
11. Android 可拍照或从相册选择单张图片，预览后写入 Windows 剪贴板，不自动粘贴且不影响文字会话。
12. 图片预览提供类似微信的“原图”选项，每次选择新图片时默认不选中。
13. 支持手机与已绑定 Windows 电脑之间的双向多文件、目录传输；手机发送到电脑自动保存，Windows 支持资源管理器拖动上传。
14. 文件传输不设置软件层面的大小上限，支持断点续传、文件完整性校验和后台继续传输。
15. 文件传输默认启用增强安全模式；基础 TLS 1.3、证书固定和绑定认证不可关闭。
16. Windows 和 Android 可通过 GitHub Releases 检查、后台下载并由用户确认安装正式更新；更新失败不影响实时输入。

## 3. V1 非目标

以下内容不在 V1 范围内：

- 公网中转和跨互联网连接。
- 手机锁屏后继续使用第三方输入法语音输入。
- 多台电脑同时广播输入。
- Windows 端读取或理解目标应用中的现有正文。
- 电脑端与手机端同时编辑同一段正在同步的文字。
- 针对终端或聊天应用的 Enter 安全策略。
- 针对单个应用的专用注入规则。
- 云同步、账户体系、统计分析和远程日志。
- 文件内容理解、自动打开或自动执行。
- 静默更新、强制更新、增量补丁、灰度发布和自建更新后端或 CDN。

公网中转和锁屏语音能力在后续独立评估。

## 4. 产品与工程原则

### 4.1 主路径优先

优先从问题根因和操作系统机制出发建立稳定主路径，不用多层补救、猜测性兼容和大量特殊分支掩盖基础设计问题。

每项机制必须评估：

- 对用户的直接收益。
- 降低的实际风险。
- 实现和测试复杂度。
- 对安装包体积的影响。
- 长期维护成本。

简单是重要约束，但不能以简单为理由删除已经确认的核心功能；同样，也不为尚未出现的问题预先建设复杂兜底。兼容性优化以真实设备和目标应用测试结果为依据。

### 4.2 明确而不猜测

系统能确认状态时自动处理；无法确认目标文本或光标状态时停止注入并说明具体原因，不静默覆盖、不猜测恢复。

### 4.3 最少打扰

正常输入路径中不显示权限请求、连接通知、确认弹窗或无关指标。需要的权限在首次安装阶段集中处理。

### 4.4 数据最小化

只收集和保存实现功能所需的数据。正文不上传、不进入诊断日志，Windows 不保存已完成正文历史。

## 5. 核心概念

### 5.1 绑定

手机与电脑之间建立的长期可信关系。绑定没有时间期限，直到任一端手工解绑；系统重装、应用数据清除或密钥丢失后需要重新绑定。

Android 为本机生成稳定的匿名 `phone_id` 并保存在本地；已有 ID 在重新绑定时继续复用。首次没有本地 ID 时，优先根据 Android 设备标识生成不可逆的命名空间哈希，无法取得时才使用随机 ID。Windows 以 `phone_id` 为唯一键重新配对，已有记录执行更新而不是新增；不依据手机名称合并设备。

### 5.2 输入会话

一次从手机开始、以用户点击“新会话”结束的文本同步过程。每个会话具有唯一 `session_id` 和从小到大递增的 `sequence`。用户点击“同步”只把当前完整文本发送到选定电脑，不结束会话；只有“新会话”会清空输入并开始下一段。

### 5.3 目标窗口

会话产生第一个字符时，Windows 的前台窗口。一个活跃会话锁定一个目标窗口；窗口切换后不跟随到新窗口。

### 5.4 同步与结束

“同步”表示把当前完整文本应用到选定电脑的当前光标。目标已确认应用且本地没有新变化时，按钮置灰。同步不额外注入 Enter，也不结束会话。“新会话”结束当前会话并清空输入；已同步的非空文本写入不可变历史，未同步内容不等待 Windows ACK，保留为手机历史后释放旧会话。

## 6. 首次安装与绑定

### 6.1 Windows 首次运行

1. 安装或首次运行时立即申请管理员权限。
2. 安装高权限注入助手、默认开机启动项和局域网防火墙规则。
3. 启动普通权限托盘程序并显示绑定二维码。
4. 电脑名称默认使用 Windows 设备名，用户可以稍后修改。

防火墙规则允许所有 Windows 网络配置中的 `LocalSubnet`，避免手机热点或被标记为公用网络的家庭网络无法使用。未绑定设备无法通过应用层身份认证。

### 6.2 Android 首次运行

1. 首屏进入添加电脑流程。
2. 用户授权相机并扫描 Windows 显示的二维码。
3. Android 校验二维码携带的电脑身份和 TLS 证书指纹。
4. 手机生成该电脑专用的身份密钥并完成注册。
5. 扫描成功即完成绑定，不再要求验证码或电脑端二次确认。
6. 自动进入输入页，选中新绑定的电脑并唤起当前系统输入法。

### 6.3 二维码规则

- 二维码只在绑定窗口打开时接受使用。
- 每个二维码只允许成功绑定一次。
- 二维码成功使用后立即失效。
- 界面不显示倒计时，避免与永久绑定关系混淆。
- 再绑定一部手机时生成新的二维码。

### 6.4 解绑

- Android 和 Windows 均可查看并手工解绑设备。
- 在线解绑时通知另一端并立即断开。
- Windows 端解绑后，原手机密钥不能再次通过认证。
- Android 离线解绑时删除本地密钥；Windows 可能保留一条无效设备记录，可在电脑端删除。
- 解绑需要一次确认，不要求密码或验证码。

## 7. 日常输入流程

1. Windows 随用户登录自动启动并停留在托盘。
2. Android 打开说写，自动连接上次使用的电脑。
3. 输入页自动聚焦文本框并唤起当前系统输入法。
4. 用户在 Windows 中放好目标光标。
5. 新会话状态下，Android 优先选择 Windows 最近报告鼠标活动的在线电脑；无法确认时保留上次选择并等待用户手工选择。产生文本后创建会话并锁定 Windows 当前前台窗口。
6. 后续新增、删除和替换接近实时地同步。
7. Android 按文本变化自动发送；需要把全文重新写入当前光标时，用户点击“同步”。
8. Windows 对每个完整状态返回 ACK；收到 ACK 后本地同步状态更新。
9. 用户点击“新会话”结束本段，非空内容写入历史，输入框清空并创建新的空会话。

不设置“开始输入”按钮，不要求 Windows 端选择目标应用。

正常连接时，`start` 直接携带第一份完整文本并锁定目标。会话开始后即使正文被全部删空，用户仍可点击“新会话”结束；Windows 确认删除完成后关闭会话，但 Android 不保存空历史记录。

## 8. Android 功能需求

### 8.1 输入页

- 使用 Android 原生多行文本编辑能力。
- 原样保留 Unicode 文本和换行，不把换行替换为空格。
- 每次文本变化均生成新的完整状态和递增序号。
- 草稿、会话 ID、序号和目标电脑自动保存。
- 返回、切换到后台或进程被系统回收时不自动创建新会话或清空输入。
- 重新打开后恢复未完成会话。
- 输入法收起时关闭输入界面：悬浮模式回到悬浮球；完整输入页结束 Activity，回到悬浮球状态（未开启悬浮模式时返回系统桌面）。该动作不等于新会话，不清空草稿。
- 输入区下方固定显示绑定电脑横向选择栏和 `[清空] [图片] [同步] [新会话]` 操作栏，不因多按钮挤压文本区域。清空按钮位于操作栏最左侧。
- “清空”只清空当前输入草稿，不结束会话、不写入空历史；活跃会话立即发送空的完整文本状态，同步删除 Windows 当前会话已注入的文本。输入为空或正在结束时按钮置灰。
- 电脑选择栏可在任意会话状态点击。每台电脑独立保存草稿、`session_id`、序号、确认序号和结束状态；切换时旧电脑会话保持，不发送完成或取消，切回后通过 `resume` 继续原会话。
- “同步”统一处理首次全文同步、目标失效后的当前光标同步和电脑切换后的全文同步；目标已确认应用且文本没有变化时置灰。
- 连接状态使用文字与颜色/图标共同表达，不能只依靠颜色。

Android 唤起用户当前选择的系统输入法，不识别、不指定或切换到任何特定输入法。

### 8.2 历史

- 历史默认永久保存在手机本地，不自动清理。
- 按会话结束时间倒序排列。
- 列表显示时间、电脑名称和两行正文预览。
- 详情页只读，支持复制、作为新输入和删除。
- 历史列表支持进入批量选择模式；每条记录显示复选框，顶部显示已选数量，并提供全选和批量删除。
- 批量删除一次确认后以单个本地事务执行；退出选择模式不改变未选记录。详情页保留单条删除。
- “作为新输入”创建新会话，不修改旧记录。
- 点击历史记录不得自动向 Windows 注入。
- V1 不提供搜索、标签、收藏或云同步。

### 8.3 多电脑

- 一台手机可以永久绑定多台电脑。
- 同一时刻只向一台电脑输出，不支持广播。
- 默认选择上次使用的电脑。
- 没有文本或处于新会话状态时，优先立即选择最近鼠标活动且在线的电脑；无法确认时不猜测。
- 输入页在操作栏上方显示一行绑定电脑选择栏，可随时手工切换，不受是否有文本限制。
- 电脑列表支持添加、重命名和解绑。
- 设置只提供“自动选择电脑”总开关和简短说明，不再提供“参与自动选择的电脑”或逐台开关。
- 自动选择在新会话状态下执行，而不是等到第一个字符；手机通过已认证的轻量控制连接读取各电脑的在线状态和最近活动信息，不传输正文。
- 无法区分多个候选时保留手机正文并提示手工选择，不广播、不猜测、不在输入会话中途自动切换电脑。
- 电脑栏不显示“当前”“最近活动”等文字；手机选中的电脑使用青绿色边框/勾选图标，最近鼠标活动电脑使用蓝色指针图标，连接状态使用状态点。所有图标提供无障碍描述。

### 8.4 屏幕模式

- 输入页采用纯黑背景，避免渐变、装饰插画和卡片式仪表盘。
- “操作后保持屏幕亮 10 分钟”默认开启，只在输入页处于前台时生效；每次触摸、键盘或语音文本变化都会重新计时。
- “极暗模式”降低当前页面亮度并使用低亮度文字，记住上次选择。
- 输入页提供快速切换极暗模式的图标按钮。
- 应用不能承诺控制第三方输入法主题，也不能承诺锁屏后输入法继续工作。

### 8.5 页面结构

Android V1 只有三个主要内容页面：

- 输入。
- 历史。
- 电脑。

输入页顶部通过图标进入历史和电脑页面，避免系统输入法弹出时底部导航占用空间。设置从右上角菜单进入。

### 8.6 悬浮输入模式

悬浮输入是主输入流程的可选入口，不是独立会话、独立历史或第二套同步机制。完整应用与悬浮输入始终共享选定电脑、草稿、`session_id`、`sequence` 和同步/结束状态。

- 功能默认关闭。用户在设置中主动开启时，应用先说明用途，再进入 Android 系统的“显示在其他应用上层”授权页面。
- 未授权、关闭悬浮输入或系统停止悬浮服务，不影响普通输入、历史、电脑切换和绑定功能。
- 收起状态显示一个 48dp 半透明圆形悬浮球；只有悬浮球区域接收触摸，不遮挡或拦截其他应用的其余区域。
- 单击悬浮球打开键盘上方的快速输入面板，自动聚焦原生多行文本框并唤起用户当前系统输入法。
- 按住并拖动悬浮球可以移动位置；松手后吸附到最近屏幕边缘，并记住位置。
- 双击悬浮球进入完整应用，并无损保留当前草稿和会话。
- 快速面板只显示绑定电脑选择栏、明确连接状态、多行文本框、收起图标和 `[清空] [图片] [同步] [新会话]` 操作栏；历史、电脑管理和设置留在完整应用中。
- 快速面板与完整输入页使用相同的电脑切换、图片、同步和新会话功能，不建立第二套按钮逻辑。
- 单击收起、返回或离开快速面板不等于新会话，不清空文本，也不创建历史。
- 拖动时显示底部关闭区域；拖入后关闭悬浮模式并停止常驻服务，但保留未完成草稿。
- 完整输入页位于前台时隐藏悬浮球；系统输入法收起或用户通过系统手势离开输入界面时，完整 Activity 退出并恢复悬浮球，避免只收起输入法后留下空的输入页。
- 离线时仍允许编辑并保存最新完整状态；“同步”在连接恢复且用户确认目标后发送，“新会话”不等待 Windows ACK。
- 悬浮模式运行时允许显示 Android 要求的低打扰常驻通知，并提供“关闭悬浮输入”动作。

悬浮输入不提供自有麦克风或语音识别按钮；语音能力仍由用户当前系统输入法提供。

## 9. Windows 功能需求

### 9.1 后台运行

- 默认随 Windows 用户登录自动启动。
- 日常启动后直接进入托盘，不弹主窗口。
- 手机连接、开始输入和新会话时不弹系统通知。
- 关闭管理窗口只隐藏到托盘；“退出说写”才结束程序。
- 托盘提示文字反映等待连接、已连接、正在输入和等待目标窗口等实际状态。

### 9.2 文本注入

- 会话第一个字符到达时锁定当前前台窗口。
- 只向锁定窗口注入，不随 Windows 前台窗口变化而切换目标。
- 用户通过鼠标点击、滚轮或键盘接管电脑后，立即停止旧会话并释放输入权。
- 仅由程序造成的目标窗口失焦不立即销毁会话；原窗口恢复且输入租约仍有效时才应用最新状态。
- Windows 不读取目标应用现有正文，只维护本会话已经注入的逻辑状态。
- 电脑端移动光标、修改正在同步的内容或改变选区会终止旧会话；Android 保留全文，用户可在新光标建立新会话。
- 支持中文 Unicode，并重点验证 VS Code、Codex、主流浏览器和常用终端。

Windows 根据上一次已应用文本和新文本计算差异。基础算法按 Unicode 字素边界确定最长公共前缀，退格删除旧文本剩余部分，再注入新文本剩余部分。该算法需覆盖手机文本中的任意新增、删除和替换。

Android 文本中的换行在 Windows 端直接作为 Enter 注入。V1 不识别终端、不阻止命令执行、不针对应用改变 Enter 行为。“新会话”本身不额外注入 Enter。

### 9.3 管理员目标

说写必须支持向管理员权限运行的目标应用注入文本，同时避免让网络监听和协议解析长期运行在高权限进程中。

采用以下权限边界：

- 普通权限主程序负责 WSS、绑定、协议、托盘和管理界面。
- 高权限注入助手只处理严格限定的文本注入指令。
- 首次安装时创建当前用户登录触发的高权限计划任务。
- 正式环境只允许该计划任务启动注入助手；主程序不得再直接启动另一个普通权限助手。
- 正常运行期间不在输入过程中请求 UAC。
- 两个进程通过受保护的本地管道通信。
- 注入助手验证调用进程身份和受保护的安装路径，主程序反向验证助手路径、IPC 版本、实例 ID 和高权限状态。
- 注入助手不监听网络、不保存正文、不持有长期绑定密钥。
- 不使用运行在 Session 0 的 Windows Service 完成桌面输入注入。

UAC 安全桌面、登录界面和系统级安全界面不属于支持目标。

### 9.4 管理窗口

Windows 管理窗口使用紧凑的原生界面，包含：

- 状态。
- 已绑定手机。
- 设置。

状态页只显示连接手机、当前目标、局域网地址和真实错误，不展示速度图表或无实际用途的统计指标。

设置页只提供电脑名称、开机自动启动、注入助手状态、修复注入助手和版本信息。输入助手未运行时，Windows 通过已注册的高权限任务启动唯一实例；管道中断后先重新握手并核对会话状态，不结束进程、不另起普通权限助手。端口、证书和日志级别不直接暴露给普通用户。

### 9.5 多手机

- 一台电脑可以绑定多部手机。
- 同一时刻只接受一部手机的活跃输入会话。
- 另一部手机尝试开始时，显示电脑正在接收其他手机输入。

## 10. 用户可见状态

界面不使用含义不明的“已暂停”。状态必须说明原因或下一步动作，例如：

- `已连接到：办公室电脑`
- `正在输入到：Visual Studio Code`
- `请在电脑上回到 Visual Studio Code`
- `正在重新连接：办公室电脑`
- `办公室电脑已离线`
- `等待电脑同步完成`
- `原输入窗口已关闭`
- `Windows 输入服务不可用`
- `绑定已失效，请重新绑定`

内部协议可以使用 `paused` 等技术状态名，但不得直接展示给用户。

## 11. 异常状态与恢复

| 场景 | V1 行为 |
| --- | --- |
| Wi-Fi 短暂断开 | 手机继续编辑并保存最新完整状态，自动重连 |
| Wi-Fi 恢复 | 目标窗口仍有效时自动补齐 |
| Windows 切换窗口 | 停止注入，要求回到原窗口 |
| 回到原窗口 | 自动补齐，不要求点击继续 |
| Android 进入后台 | 保留会话，不自动完成 |
| Android 进程被回收 | 重新打开后恢复文本、会话 ID 和序号 |
| 电脑休眠和唤醒 | 自动重连并继续内存中的原会话 |
| 电脑离线时开始新草稿 | 只在 Android 本地保存；重连后提示用户放好电脑光标并点击“同步” |
| 目标应用关闭 | 原目标失效，不自动选择新窗口 |
| 电脑重启 | 原目标失效，不自动恢复或猜测光标 |
| Windows 主程序状态丢失 | 原目标失效，不承诺无重复恢复 |
| 主程序与同一注入助手断管 | 查询助手会话；已应用则自动补 ACK，未应用则安全重试 |
| 注入助手实例已更换或结果无法确认 | 自动恢复服务连接，保留手机全文并提示用户点击“同步”创建新会话 |
| TSF 组件不可用或版本不一致 | 不注入、不回退按键路径，保留手机全文并明确提示输入服务不可用 |
| 同步期间断线 | 保留最新完整状态，重连后继续；目标失效时要求用户放好光标并点击“同步” |
| 用户开始新会话 | 手机保存当前非空全文历史，释放旧会话，不等待 Windows ACK，立即允许新输入 |

电脑重启、目标应用关闭或 Windows 状态丢失后，Android 保留完整文本并提供“从当前光标重新输入全文”。用户重新放置光标后，该操作创建新会话并注入完整文本；系统不尝试读取、删除或合并旧目标中的内容。

## 12. 传输与一致性

### 12.1 传输选择

V1 使用 WSS，即 WebSocket over TLS。WebSocket 运行在 TCP 上，并提供消息边界、标准心跳和成熟客户端生态。V1 不采用裸 TCP 自定义分帧，也不采用普通 `ws://` 叠加自定义正文加密。

### 12.2 安全传输

- 使用 TLS 1.3。
- Android 固定从二维码获得的电脑证书指纹。
- 未绑定设备不能进入输入协议。
- 配对和输入正文均通过加密连接传输。
- 文件控制面和正文均通过加密连接传输；完整设计见 [文件传输设计基线](file-transfer-design-v1.md)。

### 12.3 消息类型

协议至少包含：

```text
pair       首次绑定
auth       已绑定手机认证
start      创建输入会话
update     完整文本状态
ack        已成功应用的序号
finish     最终状态和冻结请求
resume     连接恢复时提交最新完整状态
target     目标窗口状态
health_check / health_ack  空闲后首次编辑的应用层存活确认
switch_computer / switch_ack  Windows 悬浮球切换电脑及确认
error      明确错误代码
```

传输层存活使用 WebSocket 协议原生 Ping/Pong。两端通过 `ready.capabilities` 明确协商后，空闲首次编辑还可使用不经过注入服务的 JSON 健康确认；旧版本不发送该消息。V1 不为正文消息增加通用消息 ID、时间戳、正文哈希或逐条签名。

`update` 至少包含：

```text
protocol_version
device_id
session_id
sequence
full_text
```

### 12.4 顺序与重发

- 每次 Android 文本变化递增 `sequence`。
- `sequence` 是从 1 开始的正数 64 位有符号整数，允许因待发送状态合并而跳号。
- `start` 携带第一份完整文本和序号，不创建无正文的网络会话。
- Windows 只处理大于最后已应用序号的状态。
- 尚未开始注入的过期中间状态可以被更新的完整状态替代。
- Android 最多保留一个等待 ACK 的状态和一个最新待发送状态。
- 重复状态返回已有 ACK，不重复注入。
- 本地注入管道中断后，只有同一助手实例明确报告“已应用”或“尚未应用”时才自动恢复；实例变化或状态冲突不得盲目重放正文。
- 同一会话和序号出现不同正文时停止会话并返回协议错误。
- 乱序到达的旧状态被忽略。
- 断线期间 Android 保留最新完整状态。
- 重连后双方根据最后 ACK 补齐差异。
- `finish` 再次携带最终完整文本和最终序号，只有该状态已应用后才能得到最终 ACK。
- “同步”在普通编辑状态直接发送当前完整文本；目标失效、电脑切换或离线恢复时，同一按钮改为从当前光标同步全文。
- “新会话”结束当前会话并创建新的空会话。它不等待 Windows ACK；Android 先保存非空手机全文历史，再释放旧 Windows 会话。旧目标中已经写入的部分文本不回滚。
- 同步状态已确认且文本未变化时，“同步”置灰；切换到另一台电脑或文本再次变化时重新启用。
- 得到 ACK 后，相同 `session_id` 的已应用序号仍遵守顺序规则；用户开始新会话后不得再修改旧会话。
- 协议可继续使用 `finish`/`cancel` 作为内部结束和释放消息，但这些名称不直接显示给用户。

序号机制保证双方进程仍保留会话状态时的网络重发一致性。由于全局文本注入与本地持久化无法组成事务，Windows 进程或电脑重启后不承诺自动实现恰好一次恢复。

Android 草稿允许在不超过 200 ms 的短窗口内合并落盘，并在进入后台、切换输入表面和点击“新会话”时立即提交。Windows 不持久化输入事务日志；异常恢复以保留手机完整正文为优先。

## 13. 发现与多地址

- 初次绑定使用二维码中的多个候选地址和电脑身份，并逐个尝试到首个完整收到 `ready` 的地址。
- 首次成功后只保存该固定地址并丢弃其他候选；后续断线、重启和 mDNS 发现都不得自动更换地址。
- 局域网发现只广播服务类型、随机电脑 ID、端口和协议版本。
- 不广播电脑自定义名称、Windows 用户名或已绑定手机。
- mDNS 只更新在线状态；固定地址变化时用户需要重新添加电脑。
- V1 不提供手工填写 IP 或配对码。

## 14. 密钥与本地数据

### 14.1 Android

- 每台电脑使用独立的 Android Keystore P-256 身份私钥。
- 私钥不可导出，并且不要求每次使用时进行生物识别或锁屏认证。
- 电脑保存手机公钥，通过随机挑战签名认证手机。
- Android 保存电脑证书指纹和连接元数据。
- 历史正文和草稿使用 Keystore 中的 AES 密钥进行 AES-GCM 字段加密。
- 不引入仅用于整库加密的大型运行时依赖。
- V1 禁止敏感数据参与 Android 系统应用备份。
- 卸载、清除数据、恢复出厂或密钥失效后需要重新绑定。

历史默认永久保存。删除单条记录为应用级逻辑删除，不承诺对闪存进行物理级安全擦除；清空全部历史时销毁并重新生成历史加密密钥，使原密文无法继续解密。

### 14.2 Windows

- TLS 私钥和电脑身份私钥通过当前用户作用域的 Windows DPAPI 保护。
- 永久保存已绑定手机公钥、设备名称和设置。
- 不永久保存已完成正文。
- 活跃会话正文和序号只保存在内存中。
- Windows 重装、更换用户或 DPAPI 数据失效后需要重新绑定。

“永久绑定”表示两端应用数据和系统身份未被重置时没有时间期限，不表示密钥可以跨系统重装或设备迁移。

## 15. 隐私与日志

发布版本可以记录：

- 时间。
- 连接和断开事件。
- 会话 ID 的短哈希。
- 序号和文本长度。
- 目标进程名称，不记录完整窗口标题。
- 错误代码和协议版本。

禁止记录：

- 输入正文。
- 二维码内容。
- 私钥、签名和认证凭证。
- 完整设备标识。
- Android 历史内容。

日志限制大小并滚动清理。V1 不接入分析 SDK、广告 SDK、云端崩溃收集或远程日志。

## 16. 安全边界

V1 需要防止：

- 局域网窃听和传输篡改。
- 未绑定手机向电脑注入文字。
- 重复使用旧二维码新增绑定。
- 直接复制应用文件后读取正文和私钥。
- 通过普通网络进程直接获得 Windows 高权限。

V1 不承诺防御已经取得 Android root、Windows 管理员权限、屏幕读取能力、恶意输入法权限或目标应用控制权的本地攻击者。

## 17. 性能与体积目标

- 稳定局域网中，从 Android 文本变化回调到 Windows 开始对应注入的目标 P95 延迟不高于 100 ms，不包含输入法自身语音识别耗时。
- 网络恢复后优先同步最新完整状态，避免陈旧更新造成持续排队。
- Android 和 Windows 均避免非必要的大型 UI 运行时、浏览器内核和遥测依赖。
- 每次发布记录 Android APK/AAB 和 Windows 安装包、主程序、注入助手的实际大小。
- 精确体积预算在技术验证获得首个可运行构建后确定。

## 18. V1 验收条件

1. Windows 首次安装集中完成权限、开机启动和防火墙设置，输入过程中不再弹 UAC。
2. Android 扫描一次二维码即可永久绑定固定地址；电脑 IP 变化时删除并重新添加电脑。
3. Android 能使用当前系统输入法，输入法产生的新增、删除和替换会触发同步。
4. 中文、英文、标点、换行以及已有内容的新增、删除和替换能同步到 Windows。
5. VS Code、Codex、Chrome、Edge、Windows Terminal 和 PowerShell 完成兼容性实测并记录结果。
6. Windows 切换目标窗口后不会把后续内容注入新窗口；回到原窗口后能自动补齐。
7. 网络短暂断开后不会因协议重发重复注入已经确认的状态。
8. “新会话”后旧会话冻结，不会继续修改，并且不会额外发送 Enter。
9. Android 历史可查看、复制、作为新输入、单条删除和批量选择删除。
10. 一台手机可切换多台电脑，但不会同时广播。
11. 普通权限和管理员权限目标均可输入，UAC 安全桌面除外。
12. 抓取局域网流量不能获得正文或认证凭证明文。
13. 发布日志中不出现输入正文、二维码或密钥材料。
14. 悬浮球可单击输入、按住拖动和双击进入完整应用，并与完整应用共享同一草稿、电脑切换、图片、同步和新会话状态；输入法收起时两种输入界面都退出到悬浮球；关闭或拒绝悬浮权限不影响其他功能。
15. Android 可以多选文件、选择目录并发送到当前电脑；Windows 自动保存到配置目录，不要求接收确认。
16. Windows 可以选择或拖动多个文件、目录发送到手机；Android 对整个批次确认一次并选择保存目录。
17. 文件和目录传输保持相对路径，冲突不覆盖，断点恢复后不重复已经校验完成的文件。
18. 文件传输过程中实时文字输入仍保持既定延迟和顺序，不因大文件排队。
19. 断网、Android 进程重启、Windows 主程序重启和电脑重启后，未完成批次可以继续。
20. 文件传输不设置软件层面的文件大小或总大小上限；大文件传输不导致内存随文件大小线性增长。
21. Windows IoT、普通 Windows 和 Android 的文件传输均验证 TLS、绑定认证、路径校验、哈希完整性和临时文件清理。
22. 两端可从 GitHub Releases 发现正式更新，后台下载时显示进度并支持由系统恢复中断；清单签名、SHA-256 或平台签名校验失败时拒绝安装。
23. 更新检查和下载失败、GitHub 不可达、下载或安装被取消时，当前版本和实时输入仍可正常使用；活动输入会话期间不启动安装。

## 19. 已确定的技术基线

- Android 最低版本为 Android 10（API 29）。
- Windows 支持 Windows 10 22H2 和 Windows 11，V1 先发布 x64。
- Android 使用 Kotlin、XML 和原生 Views，不使用 Jetpack Compose。
- Android 悬浮输入使用系统应用上层窗口和仅在该模式开启时运行的轻量前台服务，不使用无障碍服务。
- Windows 使用 Rust、Win32 和 Common Controls，不使用 Slint、WebView 或 WinUI 3。
- 局域网传输使用 WSS/TLS 1.3，业务消息使用 JSON。
- Android 使用 OkHttp、Android Keystore、原生 SQLite 和系统局域网发现能力。
- 文件正文使用独立 HTTPS/TLS 流式通道，控制面继续使用已认证 WSS；详细文件边界见 [文件传输设计基线](file-transfer-design-v1.md)。
- Windows 使用 `windows`、`tokio`、`tokio-tungstenite`、`rustls` 和原生 Windows 系统能力。
- Windows 安装包使用 Inno Setup；两端在线更新直接使用 GitHub Releases、签名清单和系统后台下载能力，详细边界见 [GitHub 在线更新设计基线](update-design-v1.md)。
- 各目标应用中的 Unicode、字素退格和 Enter 注入细节通过真实兼容性验证确定。
- 精确体积预算在首个可运行 Release 构建后复核。

完整设计见 [V1 技术方案](architecture-v1.md)。
