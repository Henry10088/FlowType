## 1. 设计目标

界面服务于一条主路径：用户在手机上调用当前系统输入法进行语音或键盘输入，文字实时出现在电脑当前目标窗口中。

- 首次绑定步骤短，扫码成功后直接进入输入。
- 日常输入不需要“开始”操作，不打断语音输入。
- 连接、目标和异常状态必须用文字说清楚，不能只依赖颜色或技术术语。
- 高频操作靠近用户当前注意区域，低频配置不占据主界面。
- 优先使用平台原生交互习惯，避免营销页、仪表盘和 AI 产品常见的装饰性视觉。
- 简单不是删功能。每项设计同时评估用户收益、实现成本和缺失后的影响，优先从根因解决问题，避免无证据的补救机制。

## 2. 视觉基础

### 2.1 颜色

全产品只使用一个品牌强调色：`#00BAB8`；连接和活动状态使用固定的语义色，不作为装饰色。

| 用途 | Android | Windows |
| --- | --- | --- |
| 主背景 | `#000000` | 系统亮色背景，基准 `#FFFFFF` |
| 次级表面 | `#101214` | 系统浅灰，基准 `#F5F6F7` |
| 主文字 | `#F4F6F7` | `#202124` |
| 次文字 | `#8E969D` | `#687078` |
| 分隔线 | `#24282B` | `#E2E5E7` |
| 强调和选中 | `#00BAB8` | `#00BAB8` |
| 已连接 | `#00BAB8` | `#00BAB8` |
| 未连接/重连 | `#F59E0B` | `#F59E0B` |
| 最近活动标记 | `#3B82F6` | `#3B82F6` |
| 未绑定/无状态 | `#7A848C` | `#7A848C` |
| 错误 | `#D64545` | `#D64545` |

- 强调色只用于当前选择、连接状态点、复选框和关键焦点，不铺满大面积背景；蓝、橙、灰、红只按上表语义使用。
- 错误必须同时提供明确文字；即使使用系统错误色，也不能只靠红色表达。
- 不使用渐变、玻璃效果、彩色光晕、装饰性阴影或多套强调色。

### 2.2 字体

- Android：系统默认无衬线字体，中文跟随系统字体。
- Windows：`Segoe UI` 与 `Microsoft YaHei UI`，跟随系统字体回退。
- 不使用负字距，不按窗口宽度连续缩放字号。

| 层级 | Android | Windows |
| --- | --- | --- |
| 页面标题 | 22sp，Semibold | 24px，Semibold |
| 重要对象名称 | 18sp，Semibold | 16px，Semibold |
| 正文和控件 | 16sp，Regular | 14px，Regular |
| 分组标题 | 14sp，Semibold | 14px，Semibold |
| 辅助文字 | 13sp，Regular | 12px，Regular |

同一层级在所有页面保持相同大小和粗细。电脑名称、手机名称等主要对象名称不得退化为辅助字号。

### 2.3 间距和形状

- 基础间距单位为 4，常用间距为 8、12、16、24、32。
- 页面内容按统一左边界对齐，不用视觉上随机的缩进。
- 普通按钮和输入框高度保持一致：Android 48dp，Windows 34px。
- 卡片圆角不超过 8；按钮和输入框圆角为 4 至 6；不使用胶囊形按钮。
- 页面分组优先使用留白和细分隔线，不把每一段内容包成卡片。

### 2.4 图标

- 使用平台熟悉的线性图标：历史、电脑、扫码、复制、删除、更多、亮度、窗口、二维码和电源。
- 图标按钮必须有无障碍名称和悬停提示；常用图标不附加重复说明文字。
- 不使用 emoji、手绘图标或装饰性插画。

## 3. Android

### 3.1 全局框架

- 设计基准宽度为 390dp，必须适配较窄手机和系统字体放大。
- 输入相关页面为纯黑背景，内容延伸到系统安全区域内侧。
- 不使用底部导航，避免系统输入法弹出后挤压输入空间。
- 历史和电脑通过输入页顶部图标进入；设置类低频操作放在右上角菜单。

### 3.2 输入页

视觉基准：`docs/ui-prototypes/android/input-option-2-revised-v1.png`。

- 打开应用后在新会话状态优先选择最近鼠标活动的在线电脑；无法确认时保留上次选择，聚焦多行文本框并唤起当前系统输入法。
- 顶部显示选定电脑和明确连接状态；电脑名称是主要信息，字号和字重不得过小。
- 中部是无装饰的原生多行文本输入区域，保留空行、换行和完整 Unicode。
- 文本区下方固定放置一行绑定电脑选择栏，再放置 `[图片] [同步] [新会话]` 三个操作按钮；按钮区域不挤压文本区，三者尺寸和间距统一。
- 电脑选择栏可在任意会话状态切换。每台电脑显示并恢复自己的草稿与同步状态；切换不会完成、取消或转移另一台电脑的输入会话。
- “同步”在文本未变化且目标已确认应用时置灰；目标切换、目标失效或文本变化时恢复可用。
- 页面提供历史、电脑和极暗模式图标入口；设置使用主流齿轮图标。
- 输入法收起或系统手势离开输入界面时，完整 Activity 退出并恢复悬浮球；未开启悬浮输入时结束 Activity 返回系统桌面。该动作不清空草稿、不创建历史。

状态文案按真实情况切换：

- `已连接到：办公室电脑`
- `正在输入到：Visual Studio Code`
- `请在电脑上回到 Visual Studio Code`
- `正在重新连接：办公室电脑`
- `办公室电脑已离线`
- `等待电脑同步完成`
- `原输入窗口已关闭`
- `Windows 输入服务不可用`

不得显示含义不明确的“已暂停”。

连接和电脑标记使用统一语义：品牌绿 `#00BAB8` 表示已连接，橙色 `#F59E0B` 表示已绑定但未连接或正在重连，灰色表示未绑定/无可用状态，红色只表示错误。颜色旁必须保留文字或图标。电脑选择栏不显示“当前”“最近活动”等文字：青绿色边框或勾选图标表示手机选中电脑，蓝色指针图标表示最近鼠标活动电脑；两者同时存在时叠加两个小标记，并提供无障碍描述。

### 3.3 同步与新会话

- 点击“同步”发送当前完整文本，不结束会话；按钮旁的状态区域显示“已同步”“待同步”“正在同步”或明确错误。
- 目标失效、电脑切换或重连后，“同步”统一执行从当前 Windows 光标同步全文，不另设“同步到当前光标”按钮。
- 文本已经被目标确认应用且没有变化时，“同步”置灰；再次编辑后自动恢复。
- 点击“新会话”结束当前会话并清空输入框，创建新的空会话。已同步的非空文本写入历史；未同步内容也先保留为手机历史，但不等待 Windows ACK。
- “新会话”不额外注入 Enter；旧会话结束后不得继续修改。

### 3.4 历史

视觉基准：`docs/ui-prototypes/android/history-v4.png`。

- 按会话结束时间倒序显示。
- 每行显示会话结束时间、加大加粗的电脑名称和最多两行正文预览。
- 字体颜色只使用白、冷灰和统一的 `#00BAB8`，不为不同记录随机分配颜色。
- 列表顶部提供选择图标；进入选择模式后每行左侧显示 checkbox，顶部显示选中数量，并提供全选和删除。
- 批量删除需要一次确认并以单个事务执行；未选记录保持不变，退出选择模式不会删除内容。
- 点击进入只读详情；详情支持复制、作为新输入和删除。
- “作为新输入”创建新会话，不修改历史记录，也不立即向 Windows 注入。

### 3.5 电脑

视觉基准：`docs/ui-prototypes/android/computers-v1.png`。

- 电脑名称是列表的主标题，使用 18sp Semibold。
- 明确显示在线、离线、正在连接和选中状态，状态同时包含文字与颜色/图标。
- 任意会话状态都可以点击电脑；切换后恢复所选电脑自己的草稿与同步状态，切回时继续原会话。
- 页面提供添加电脑、重命名和解绑；解绑需要一次确认。
- 不展示端口、IP、证书指纹和调试信息。
- 设置仅保留“自动选择电脑”总开关和一行说明，删除“参与自动选择的电脑”及逐台开关。
- 自动选择在新会话状态执行；失败时输入页保留正文并要求手工选择。

### 3.6 扫码绑定

视觉基准：`docs/ui-prototypes/android/pairing-scan-v1.png`。

- 相机权限在进入扫码流程时一次性申请，并先给出简短用途说明。
- 取景框保持稳定，不使用扫描动画或装饰光效。
- 扫码成功后不再要求验证码或电脑端确认，直接进入输入页并唤起当前系统输入法。
- 二维码失败时说明具体原因，并保留“重新扫描”动作。

### 3.7 极暗和常亮

- “保持屏幕常亮”默认开启，只在输入页位于前台时生效。
- 极暗模式降低当前 Activity 亮度，并同步降低正文和状态文字亮度；强调色保持可辨认但不刺眼。
- 极暗模式记住上次选择，入口为输入页上的图标按钮。
- 不承诺改变第三方输入法主题，也不在 V1 承诺锁屏后继续语音输入。

### 3.8 悬浮输入

视觉基准：`docs/ui-prototypes/android/floating-input-v1.png`。

- 悬浮输入默认关闭，从设置中的“悬浮输入”开关启用；授权说明必须明确写出“用于在其他应用上方快速输入到电脑”。
- 收起状态为 48dp 圆形悬浮球，触控区域不小于 56dp；空闲透明度约 55%，触摸、拖动和展开时恢复到约 90%。
- 悬浮球使用白色线性输入图标和小面积 `#00BAB8` 连接点；连接点只是辅助提示，展开后仍必须显示明确状态文字。
- 单击打开图 1 所示的键盘上方快速输入面板；面板使用 `#101214` 背景，不使用渐变、玻璃效果或大面积品牌色。
- 面板默认约 184dp 高，正文区域内部滚动，不随长文本无限增高；需要更大编辑空间时双击进入完整应用。
- 面板只保留绑定电脑选择栏、加大加粗的电脑名称、连接状态、多行正文、收起图标和 `[图片] [同步] [新会话]` 操作栏，不加入历史、电脑列表、设置或自有麦克风按钮。
- 面板与完整输入页共享同步状态和按钮行为；输入法收起、系统手势离开或点击收起时关闭面板并恢复悬浮球，不清空草稿。
- 按住拖动时悬浮球跟随手指，其他点击区域不响应；松手吸附最近边缘。拖动到底部关闭区时显示“关闭悬浮输入”。
- 双击悬浮球进入完整应用。为区分单击，单击响应允许遵循 Android 系统双击判定时间，但不得增加额外动画等待。
- 完整输入页在前台时隐藏悬浮球；收起、关闭、权限撤销和服务重启均不清空草稿。
- 悬浮球避开状态栏、显示缺口、系统导航区和展开后的输入法区域；横竖屏分别记住最近位置。
- 前台服务通知保持静默、低优先级且不显示角标，文案为“悬浮输入已开启”，只提供“关闭”动作。

### 3.9 版本与更新

- 设置页使用紧凑的“版本与更新”分组，显示当前版本和一个主状态，不增加独立更新首页。
- 空闲时提供“检查更新”；设置页同时提供“GitHub 仓库”和“查看更新”入口，发现新版本后提供“下载更新”。
- 使用系统 `DownloadManager` 后，在原位置显示下载进度、等待网络、正在校验、更新已下载或具体失败原因；关闭设置页不取消下载。
- 活动文字会话期间可以继续下载，但安装按钮显示“输入结束后可安装”，不突然打开系统安装界面。
- 首次需要“安装未知应用”权限时，先说明用途，再进入系统设置；不在输入过程中申请。

## 4. Windows

### 4.1 窗口框架

- 使用 Win32 Common Controls v6，跟随系统亮色主题和 DPI。
- 设计基准窗口约为 760 x 520 逻辑像素，允许按 DPI 缩放；最小尺寸约为 680 x 460。
- 左侧导航固定显示“状态”“已绑定手机”“设置”，选中项使用浅色底和 `#00BAB8` 小面积标记。
- 主内容区统一使用 32px 内边距；页面标题、分组标题和内容行共享固定栅格。
- 关闭窗口只隐藏到托盘，不结束程序。

### 4.2 状态页

视觉基准：`docs/ui-prototypes/windows/status-selected-light-v1.png`。

- 只显示连接手机、当前目标、局域网地址和真实错误。
- 状态文字是页面主信息；不展示速度、累计字数、趋势图和无操作价值的统计。
- 普通状态操作使用现代中性按钮，避免大面积品牌色和传统凸起按钮。

### 4.3 首次绑定

视觉基准：`docs/ui-prototypes/windows/pairing-qr-light-v1.png`。

- 首次运行完成权限和防火墙准备后直接打开绑定二维码页。
- 页面只说明“使用说写 Android 扫描二维码”，不显示绑定有效期倒计时。
- 二维码只允许成功绑定一次；成功后立即切换到状态页。
- 再绑定手机时生成新二维码，不复用旧码。

### 4.4 已绑定手机

视觉基准：`docs/ui-prototypes/windows/paired-phones-light-v1.png`。

- 手机名称是每行主标题，绑定或最近连接信息为辅助文字。
- 列表行使用统一高度和分隔线，不给每部手机单独套卡片。
- 行尾只保留必要操作；解绑使用确认对话框。
- 页面提供“绑定新手机”，进入新的二维码流程。

### 4.5 设置

视觉基准：`docs/ui-prototypes/windows/settings-light-v2.png`。

- 使用固定标签列和控件列，所有基线对齐。
- 页面标题 24px Semibold；分组标题统一为 14px Semibold；标签、值和按钮为 14px；说明文字为 12px。
- 三个分组仅通过留白和细分隔线区分：
  - 常规：电脑名称、保存、登录 Windows 后自动启动说写。
  - 输入服务：正常运行、可向普通和管理员窗口输入文字、修复输入服务。
  - 版本与更新：当前版本、`Windows x64`、更新状态和当前唯一可用操作。
- “保存”和“修复输入服务”均为中性按钮，不使用大面积强调色。
- 更新状态使用原位置文案和细进度条：`检查更新`、`正在检查…`、`已是最新版本`、`发现新版本`、`正在下载 42%`、`等待网络`、`正在校验`、`更新已下载`、`输入结束后可安装`或具体失败原因。
- 不显示端口、证书、日志、防火墙、更新通道、强制更新、诊断和高级设置。

### 4.6 托盘菜单

视觉基准：`docs/ui-prototypes/windows/tray-menu-light-v1.png`。

- 菜单顶部为不可点击的当前状态，状态点使用 `#00BAB8`，状态文字必须可独立表达含义。
- 活跃输入示例：`正在输入到：Visual Studio Code`。
- 状态下方依次为：
  - `打开说写`
  - `绑定新手机...`
  - 发现更新、下载中或已下载时，增加唯一一行动态更新状态，点击后打开设置中的“版本与更新”；无更新时不占位。
  - 分隔线
  - `退出说写`
- “设置”不在托盘重复出现，从主窗口进入。
- “退出说写”默认保持中性文字，只在悬停或确认对话框中表达风险。
- 动态更新状态示例为 `更新到 0.1.19...`、`正在下载更新 42%` 或 `更新已下载...`；安装仍需进入设置确认。
- 托盘提示文字随输入状态变化：等待连接、已连接、正在输入、等待目标窗口或输入服务不可用；更新不覆盖当前输入状态。

## 5. 状态和反馈

- 连接变化更新原位置文案，不弹 Windows 系统通知，不用 Toast 连续打断语音输入。
- 可恢复问题提供唯一、直接的下一步动作；例如“回到 Visual Studio Code”或“重新扫描”。
- 自动重连期间允许 Android 继续编辑并保存最新完整状态。
- 需要等待 ACK 的操作必须显示进行中状态，并防止重复提交。
- 所有危险操作都使用一次确认；确认框说明具体对象，例如“解绑 小米 14”，不使用笼统的“确定吗”。

## 6. 可访问性和适配

- 正文和控件文字对比度目标不低于 WCAG AA。
- 状态不能只依靠颜色、位置或动画表达。
- Android 支持系统字体放大；文字过长时换行，不覆盖相邻控件。
- Windows 采用 Per-Monitor DPI Awareness v2；在 100%、125%、150% 和 200% 缩放下保持清晰和可操作。
- Android 触控目标不小于 48dp；Windows 常用点击目标不小于 32px。
- 键盘焦点顺序与视觉顺序一致，Windows 控件保留可见焦点框和标准快捷键行为。
