## 2. 执行原则

- 先完成一条真实的手机到电脑闭环，再补齐外围页面，避免两端长期各自开发后集中集成。
- 正常网络波动必须不丢正文、不重复注入；极端进程或系统故障优先保留 Android 全文并停止猜测恢复。
- 简单不是删除核心功能，也不是忽略高概率风险。每项机制按用户收益、实现复杂度、包体积和维护成本决定。
- 不增加事务日志、逐消息签名、云服务、厂商专用保活或未经真实问题证明的应用专用分支。
- 临时验证代码不进入生产架构；可以复用测试数据、测试思路和经过审查的纯算法。
- Android 功能先在模拟器运行自动测试，再用普通系统输入法进行必要真机确认。
- 每个阶段都必须有可运行产物、测试结果和明确退出条件。
- 每个 Release 构建记录 Android APK/AAB、Windows 主程序、注入助手和安装包大小。

## 5. 阶段 1：生产工程与核心契约

状态：已完成。构建、测试、模拟器和体积记录见 [阶段 1 正式工程验证记录](validation/phase-1-production-engineering.md)。

### 5.1 工程结构

```text
android/                 Android 正式应用
windows/                 Rust Cargo workspace
  flowtype-core/          协议、状态机和纯算法
  flowtype-app/           普通权限主程序
  flowtype-injector/      高权限注入助手
  flowtype-tip/          目标进程内 TSF Speech Text Service
protocol/                JSON 样例、错误码和跨端测试向量
installer/               Inno Setup 配置
spikes/                  只读验证材料
```

不创建单独后端服务、共享代码生成器或跨语言框架。Android 与 Rust 通过同一组 JSON 样例和测试向量保持一致。

### 5.2 核心契约

- 固化协议版本、消息大小、必需字段和稳定错误码。
- 实现 `start`、`update`、`ack`、`finish`、`resume` 和 `target` 模型。
- 实现会话状态机、正数 `int64 sequence`、累计 ACK 和终态不可变。
- 实现相同序号不同正文、旧状态、重复状态和单连接约束。
- 实现 TSF 完整状态、序号、组合终止和重复状态测试模型。
- 建立 Android 单元测试、仪器测试和 Rust 单元测试的统一入口。
- 配置 Debug/Release 构建、版本号和生成物忽略规则。

### 退出条件

两端对同一组协议样例产生一致结果；正式 Android APK 和两个 Rust Release 可执行文件可以从空构建目录生成。

## 6. 阶段 2：最小端到端闭环

状态：已完成第一个内部可用构建。实现与验证边界见 [阶段 2 最小闭环验证记录](validation/phase-2-end-to-end.md)。

只实现第一条可用路径，不先补齐历史、悬浮输入和完整管理界面。

### Windows 最小路径

- 普通主程序生成电脑身份、启动 WSS 和显示可用二维码。
- WSS 使用 TLS 1.3，Android 按二维码中的 SPKI 指纹固定电脑身份。
- 注入助手通过受保护命名管道接收有界类型化指令。
- 第一个文本状态锁定当前前台窗口。
- 助手启用独立 Speech Text Service，并按目标 PID/线程路由到进程内 TIP。
- TIP 建立一个 TSF 组合范围，每次用手机完整状态原位替换该范围。
- 普通主程序在助手成功后发送累计 ACK。

### Android 最小路径

- 扫描二维码并保存电脑绑定。
- 自动进入正式输入页，聚焦原生多行输入框并唤起当前系统输入法。
- 发送完整状态，显示连接和目标状态。
- 通过“同步”发送最新完整状态；“新会话”结束本段并清空输入框。

### 退出条件

从全新安装开始，手机扫码一次后，可在同一局域网把中文、英文、删除、替换和换行同步到 Windows 当前光标，并正确完成一段输入。

同时记录第一组 Android APK、Windows 主程序、注入助手体积和稳定局域网端到端 P95 延迟；目标延迟不高于 100 ms。测量结果用于调整依赖，不另建一次性实现。

这一阶段形成第一个内部可用构建。

## 7. 阶段 3：一致性与安全

状态：已完成。自动重连、故障边界、密钥存储和模拟器安全验证见 [阶段 3 一致性与安全验证记录](validation/phase-3-reliability-security.md)。

### 网络与会话

- 一个等待 ACK 状态加一个最新待发送状态，网络慢时不形成无限队列。
- 自动重连、最后 ACK 交换和最新完整状态补齐。
- 目标窗口失焦、返回、关闭和 Windows 状态丢失。
- 同步期间断线、会话结束和空文本结束不写历史。
- 新草稿在电脑离线时只本地保存，用户明确执行“同步”后才锁定新目标。
- 一台电脑只接受一部手机的活跃会话。

### 密钥与本地数据

- Android 每台电脑独立 Keystore P-256 身份密钥。
- Android AES-GCM 草稿和历史字段加密，短窗口合并落盘，后台和完成时立即提交。
- Windows 当前用户 DPAPI 保护电脑私钥。
- 一次性二维码、挑战签名认证、解绑和密钥失效处理。
- 日志只记录长度、序号、协议和错误码，不记录正文、二维码和密钥。

### 权限边界

- 注入助手不监听网络、不持有绑定密钥、不保存正文。
- 命名管道 ACL、主程序身份和消息大小校验。
- TSF 编辑被拒绝、组合终止或结果未知时停止会话，不自动重试。
- FlowType 只注册 Speech 类别；登录后只激活一次，普通输入会话不得停用 Profile，也不得改变用户键盘 Profile 或目标线程 HKL。
- 电脑端主动编辑或移动选区时结束远程组合，手机保留全文并显示明确状态。
- Windows 新连接认证成功后使同一手机的旧连接失效。

### 退出条件

自动化故障测试覆盖重复、断线、重连、完成和非法消息；抓包看不到正文或认证凭证明文；失败时 Android 全文仍可恢复。

## 8. 阶段 4：Android 完整产品

状态：已完成。页面、原生 SQLite、加密历史、多电脑发现、悬浮输入和模拟器验证见 [阶段 4 Android 完整产品验证记录](validation/phase-4-android-product.md)。

### 页面与数据

- 输入、历史、历史详情、电脑、扫码和设置页面。
- 历史倒序、复制、作为新输入、单条删除和批量删除。
- 多电脑绑定、重命名、选择和解绑。
- 多电脑自动选择开关、最近活动状态、手工切换和歧义时保留正文策略。
- 草稿、当前电脑和未完成会话的进程恢复。
- 所有用户状态映射为已确认的明确文案。

### 输入体验

- 系统输入法自动唤起，多行和 Unicode 原样保留。
- 输入法唤起、收起退出输入表面并恢复悬浮球。
- 输入页常亮、极暗模式和亮度恢复。
- 悬浮权限、前台服务、悬浮球单击/拖动/双击和底部关闭区。
- 悬浮面板与完整输入页共享草稿、会话、序号、电脑切换和同步状态。

### 验证顺序

1. Android 模拟器自动测试和可见界面检查。
2. 普通真机功能检查。
3. 普通系统输入法真机输入矩阵。
4. 不同厂商系统只记录真实出现的问题，不预置专用保活分支。

### 退出条件（原版基线）

Android 可以独立完成扫码、多次输入、历史管理、多电脑切换、悬浮输入和解绑；进程回收后未完成正文仍可恢复。

### 8.1 已确认的 Android 交互修订（已实现）

本节是阶段 4 的增量变更，作为实现和验收的唯一依据：

- [x] 输入法收起或系统手势离开时，悬浮面板关闭并回到悬浮球；完整输入 Activity 退出并回到悬浮球（未启用悬浮输入时返回桌面）。不清空草稿、不创建历史。
- [x] 完整输入页和悬浮面板统一使用 `[图片] [同步] [新会话]`；删除“完成”“同步到当前光标”独立按钮和右上角刷新/重置入口。
- [x] 输入区下方增加绑定电脑横向选择栏，空会话可立即切换；有文本时保留全文、释放旧目标并标记待同步，点击“同步”后发送到新电脑。
- [x] 删除设置中的“参与自动选择的电脑”和逐台开关；新会话状态下根据在线及最近活动信息优先选择电脑，无法确认时要求手工点击。
- [x] 电脑选择栏不显示“当前”“最近活动”等文字；使用连接状态点、青绿色选中标记和蓝色活动指针图标，并提供无障碍描述。
- [x] 历史列表增加批量选择、全选、选中数量和一次确认后的批量删除，使用单个本地事务。

实现顺序：先更新会话控制器和输入法可见性处理，再统一完整页/悬浮面板按钮，随后接入电脑选择栏和状态标记，最后实现历史批量操作。以上实现已通过 Android 单元测试、Lint、模拟器仪器测试和界面检查；真机网络与系统输入法矩阵仍按发布前验收执行。

### 退出条件（修订后）

输入法收起后两个输入表面都能正确退出；两种输入表面按钮和状态一致；电脑可在任意会话状态手工切换且不会自动丢失手机全文；历史批量删除只删除选中记录；新会话不等待 Windows ACK 且旧会话不可继续修改。当前代码已满足上述条件。

## 10. 阶段 6：兼容性与发布

### 10.1 Android 矩阵

- Android 10 到开发时最新稳定版本。
- 模拟器和至少一台使用普通系统输入法的真实手机。
- 相机、Keystore、悬浮权限、输入法焦点、前台服务、横竖屏和字体放大。

### 10.2 Windows 矩阵

- Windows 10 22H2 和 Windows 11 x64。
- VS Code、Codex、Chrome、Edge、Windows Terminal 和 PowerShell。
- 普通权限与管理员权限目标。
- 100%、125%、150% 和 200% DPI。

### 10.3 安全与隐私

- 抓包验证 TLS 保护正文和认证材料。
- 重复二维码、伪造认证和已解绑手机必须被拒绝。
- 非主程序调用命名管道必须被拒绝。
- 日志、崩溃输出、数据库和安装目录不泄露正文或私钥。
- Android 备份规则排除敏感数据。

### 10.4 发布

- 审计 APK/AAB、Windows 主程序、注入助手和安装包体积。
- 验证安装、覆盖升级、卸载和重启后的状态。
- 准备 Android Release 签名、Windows Authenticode 和 SmartScreen 流程。
- 形成目标应用兼容性报告和已知限制。
- V1 不实现自动更新。

### 退出条件

需求文档中的全部 V1 验收条件通过；任何未通过项都必须有明确阻断结论，不能静默降低需求。

## 11. 阶段 7：双向文件与目录传输

状态：需求已确认，待实现。详细边界见 [文件传输设计基线](file-transfer-design-v1.md)。

### 实现范围

- Android 多选文件和目录，Windows 文件选择器和资源管理器拖放。
- 手机主动发送时 Windows 自动保存到配置目录；电脑发送时 Android 对整批次确认并选择目录。
- 控制面复用已认证 WSS，正文使用独立 HTTPS/TLS 流，不阻塞文字和图片通道。
- 使用 64 位大小、相对路径、SHA-256 和临时文件，支持多文件、目录、冲突改名和失败清单。
- 持久化批次清单、文件状态和已确认偏移，支持断网、进程重启和电脑重启后的断点续传。
- Android 后台使用前台服务继续传输；安全传输默认开启，TLS、证书固定和绑定认证不可关闭。

### 验证顺序

1. 单文件、大文件和中文文件名的流式传输。
2. 多文件、混合文件和目录结构还原。
3. Windows 资源管理器拖放和 Android 系统文件/目录选择器。
4. 断网、双方进程重启、电脑重启后的断点恢复。
5. 磁盘不足、源文件变化、权限错误、同名文件和非法路径。
6. 文件传输期间文字 P95 延迟、内存占用和磁盘临时空间。
7. TLS 抓包、批次令牌重放、未绑定设备和安全模式关闭后的边界验证。

### 退出条件

文件和目录可双向传输，手机到电脑自动保存，Windows 拖放可用；传输中断后不重复已完成内容；文件传输不造成实时输入明显延迟或数据错乱；包体积增量在实际 Release 构建中记录。

## 12. 测试分层

- Windows 目标应用的 TSF 中文、任意替换、删除、emoji 和换行行为。
- Speech TIP 启动前后及连续多轮完成、取消、失败后的键盘输入法和目标线程 HKL 不变；电脑端输入时远程组合立即让出。
- 扫码、解绑、多电脑、多手机和悬浮输入。
- 屏幕常亮、极暗模式、系统输入法切换和系统权限页面。

人工测试不能被模拟器或单元测试替代；同样，可自动化的状态机和协议测试不得只靠人工点击。

## 13. 发布前阻断项

以下任一问题存在时不得标记 V1 完成：

- Android 当前系统输入法的新增、删除或替换无法通过普通文本框观察。
- 中文出现稳定乱码或替换错误。
- 切换窗口后文字进入错误应用。
- 普通网络断开和重连造成稳定正文丢失或重复注入。
- 完成后同一会话仍能修改，或最终 ACK 前手机清空正文。
- 未绑定或已解绑手机可以进入输入协议。
- 输入过程中出现临时 UAC。
- FlowType 出现在 `Win + Space` 键盘列表、切换用户原输入法，或覆盖电脑端主动输入。
- 悬浮球收起时大面积拦截其他应用触摸，或关闭悬浮功能导致其他输入功能不可用。
- 日志或本地明文文件泄露输入正文、二维码或私钥。
- 安装或卸载遗留高权限计划任务、防火墙规则或启动项。
