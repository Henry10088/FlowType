# 文件传输设计基线

状态：已确认需求，待实现

## 1. 目标

说写支持 Android 手机与已绑定 Windows 电脑之间的高性能双向文件传输：

- 手机可以发送多个文件或目录到电脑，电脑自动保存，不逐批次弹出确认。
- 电脑可以通过文件选择器或资源管理器拖动发送多个文件或目录到手机。
- 传输中断后可以继续，不要求重新传输已经完成的内容。
- 文件传输不影响实时文字输入，也不阻塞图片剪贴板传输。

文件传输只面向已绑定电脑，不增加陌生设备广播发现，不提供公网中转。

## 2. 用户流程

### 2.1 手机到电脑

1. Android 在系统文件选择器中多选文件，或选择目录。
2. 手机主动发送后，Windows 自动接受并保存，不等待人工确认。
3. 默认保存到 `%USERPROFILE%\\Downloads\\FlowType`，目录可在 Windows 设置中修改。
4. 文件和目录保持相对路径结构。
5. 同名文件不覆盖，自动生成 `(1)`、`(2)` 等后缀。

### 2.2 电脑到手机

1. Windows 文件传输页面支持文件选择器和资源管理器拖放。
2. 支持文件、目录和混合多选，拖放后直接进入当前绑定手机的发送队列。
3. Android 对整个批次只确认一次，并使用系统目录选择器选择保存目录。
4. 手机保持目录结构写入，不为每个文件重复弹窗。

### 2.3 状态与后台

- Android 锁屏或切换到其它应用后继续传输，使用前台服务和系统通知显示进度。
- Windows 显示批次总进度、当前文件、速度、剩余时间和失败清单。
- 传输完成后不自动打开或执行文件。
- 一次只运行一个文件批次；批次内允许有限并发，优先保证大文件吞吐和断点状态简单。

## 3. 文件和目录语义

- 不设置软件层面的单文件大小或批次总大小上限，使用 64 位大小字段和流式读写；实际限制仅来自操作系统、文件系统、权限、磁盘空间和网络。
- 目录传输保留相对路径，默认包含被选择的目录名作为根目录。
- 不跟随 Windows 快捷方式、符号链接、Junction 或其它 Reparse Point，避免循环和越权读取。
- 只保留文件名和相对路径，拒绝绝对路径、`..`、NUL 和非法文件名。
- 默认保留文件修改时间，不复制 Windows ACL、所有者和平台专有权限。
- 一个文件读取失败时跳过该文件，继续其余文件，批次结束后显示失败清单。
- 文件冲突不覆盖，生成不冲突的新名称；恢复同一个批次时使用原目标和原临时状态。

## 4. 传输架构

采用类似 LocalSend 的控制面与数据面分离，但保留说写的绑定模型：

- 现有 WSS/TLS 连接只传输认证、能力、批次清单、接受/拒绝、进度、取消和恢复协商。
- 独立 HTTPS/TLS 文件通道传输文件正文，不使用 Base64，不把文件整体读入内存。
- Windows 作为文件服务端，手机上传使用 `POST`；电脑发送时手机通过已建立的出站连接下载 `GET`，Android 不需要开放入站端口。
- 文件通道使用单独端口和防火墙规则，文字端口继续保持独立。
- 每个文件按流式块传输，接收端写入临时文件，完成后校验并原子化为正式文件。

控制协议增加能力协商，旧客户端没有文件能力时仍可正常使用文字和图片功能。

## 5. 断点续传

每个批次有稳定的 `batch_id` 和清单。清单项目包含相对路径、类型、大小、修改时间和 SHA-256。

- 接收端持久化临时文件、已确认字节偏移和文件状态。
- 断线或进程重启后，双方重新认证并查询批次状态。
- 已完成文件跳过；当前文件从最后确认偏移继续；未完成文件继续写入。
- 源文件大小、修改时间或哈希变化时，只重新传输该文件。
- 传输完成后校验每个文件哈希，再标记批次完成。
- 取消任务立即清理临时文件；异常中断任务保留 7 天供恢复，之后自动清理。
- Android 对系统目录提供方不保证原子改名时，在应用私有临时区完成校验后再写入目标目录。

## 6. 安全设计

局域网不作为可信边界。基础安全能力永远开启，不提供明文传输模式：

- TLS 1.3 加密控制和文件通道。
- 电脑证书 SPKI 固定，手机和电脑使用已绑定身份认证。
- 每个批次使用一次性传输令牌，令牌绑定手机、电脑、批次和方向。
- 文件清单、路径、大小和正文均只在认证连接中传输。
- 每个文件使用 SHA-256 校验完整性，临时文件隔离，失败自动清理。
- 手机到电脑的自动保存只对用户主动选择并发送的批次生效。
- 电脑到手机仍需手机对批次确认，避免电脑端程序静默写入。

UI 可以提供“安全传输”选项，默认开启。该选项表示增强安全模式，包括严格的批次确认、一次性令牌、完整哈希校验和本地恢复状态保护；关闭时也不能关闭 TLS、证书固定和绑定认证，只能减少额外交互或本地保护。因此不会出现用户误以为已加密、实际使用明文的情况。

## 7. 包体积评估

当前发布基线约为：Android APK 0.9 MiB，Windows 安装包 3.2 MiB。文件传输不需要引入媒体库、浏览器内核或新的加密库。

预估增量：

| 组件 | 预估增量 | 原因 |
| --- | ---: | --- |
| Android APK | 约 20-100 KiB | 多选、目录选择、流式读写、传输状态和恢复状态均使用系统 API/现有 OkHttp |
| Windows 主程序 | 约 150-500 KiB | HTTPS 服务、目录遍历、临时文件、哈希和恢复状态 |
| Windows 注入助手/TIP | 约 0 KiB | 文件传输不进入高权限注入进程 |
| Windows 安装包 | 约 150-500 KiB | 主程序增量经压缩后的结果 |

不设置文件大小上限不会增加安装包体积，只会增加运行时磁盘和状态需求。原型完成后必须用干净 Release 构建重新测量，实际值作为发布记录，不以估算代替验收。

## 8. 实现验收

- 多文件、目录、混合拖放能够正确还原相对路径。
- 手机发送后 Windows 自动保存，电脑不弹接收确认。
- 电脑发送时 Android 只对整批次确认一次。
- 传输过程中实时文字 P95 延迟不因文件传输明显上升。
- 断网、电脑重启、Android 进程重启后可以继续已完成批次。
- 大文件传输不出现内存随文件大小线性增长。
- 同名文件不覆盖，非法路径不能写出目标目录。
- 关闭增强安全模式后仍无法抓到明文文件内容或绕过绑定认证。
- 目标文件系统空间不足、文件变化、权限失败等情况有明确结果和失败清单。
